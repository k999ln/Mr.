# avocadomini 完全版Bot仕様

更新日: 2026-09-05 (JST)

## この文書の役割

この文書は、サイトとTelegram Botで何を「使える」と呼ぶかを決める合格基準です。
画面や説明が存在するだけでは完成としません。利用者の入力から、保存された仕事、確認済みの成果物、通知、再開までがつながった時だけ、その機能を実働と判定します。

## 想定する利用者

1. やりたい仕事が決まっている人 — 道具を選び、依頼を普通の文章で送る。
2. 困りごとはあるが道具名が分からない人 — 仕事内容または目的から、最初に得たい成果を選ぶ。
3. 継続中の仕事がある人 — 総合司令室の「今日やること」から、受付済み・作業中・結果待ち・修正中の仕事を再開する。

専門用語、外部サービス名、設定値を知らなくても最初の成果まで進めることを必須とします。

## 共通の利用導線

```text
サイトで1〜3個選ぶ／Telegramで選ぶ
  → 総合司令室
  ├→ 普通の文章で依頼（選択中の道具を組み合わせる）
  └→ 道具の部屋 → 「この道具に頼む」→ 普通の文章で依頼
  → 永続Jobとして受付（重複受付を防止）
  → 作業中
  → 道具名つきの成果物と確認事項
  → 修正する／完了にする／司令室へ戻る
  → 「今日やること」から再開
```

外部への公開、配信、決済、返金、権限変更、送金は、この導線とは別の承認と実行receiptが揃うまで行いません。接続がない機能は、役に立つ下書き・計算・確認手順までを返し、実行済みとは表示しません。

## 10機能の最初の実働成果

| 機能 | 普通の文章から最初に返す成果 | 外部接続がない時の境界 |
|---|---|---|
| 依頼を整理 | 目的、前提、優先順位、次の3手 | 実行はせず計画を返す |
| 教材を作る | 対象者、章立て、本文またはワークの初稿 | 公開はしない |
| 内容を検証 | 主張ごとの確認済み・未確認・修正案 | 根拠を捏造しない |
| 売り場を作る | 商品名、対象者、価値、価格、販売ページ初稿 | ページ公開や価格変更はしない |
| 集客を広げる | 媒体別投稿案と配信順序 | 投稿・予約はしない |
| 見込み客を育てる | 相手の状態に合う返信・案内文の初稿 | メール・Telegramを一斉送信しない |
| 入金を確認 | 提供された注文情報の照合表と要確認項目 | 決済事業者の記録を読めない時は未確認と示す |
| 商品を届ける | 納品物、対象者、条件、確認手順 | 権限付与や送信はしない |
| 成果を測る | 数字の要約、変化、次に直す一箇所 | 未接続の数字を作らない |
| 報酬を分ける | 計算式、各人の金額、端数、確認事項 | 送金はしない |

## Jobの状態と表示

保存上の状態は次の意味で使います。

- `queued`: 受付済み。まだ実行者が受け取っていない。
- `claimed`: 作業中。期限切れleaseは再取得できる。
- `completed`: 成果物を作成済み。Telegram送信receiptの有無を別に記録する。
- `failed`: 実行失敗。失敗を完了として表示しない。
- `accepted_at`: 利用者が「完了にする」を押した時刻。成果物の作成完了とは分ける。

修正は元Jobを上書きせず、`parent_job_id`を持つ新しいJobとして残します。

## 安全性と信頼性の必須条件

- Telegramの個人チャットで、送信者IDとチャットIDが一致する場合だけ受け付ける。
- 選択中の道具はデータベースの最新値を正本とし、古いTelegramボタン内の値を権限判定に使わない。
- 同じTelegramメッセージは一度だけJob化する。
- 重複判定と一時間10件の上限は、チャット単位のデータベースロック内で同時に判定する。
- Job、選択、結果は利用者ごとに分離し、別利用者のJobを閲覧・修正・完了にできない。
- 外部効果を伴う操作は、対象・内容・費用を読み返した後の実行単位の承認とprovider receiptを必須とする。
- 秘密値をGitHub、ログ、Job本文、Telegram結果へ出さない。
- AIへ渡す利用者文は命令ではなくデータとして区切り、リポジトリ・端末・環境変数を調べさせない。
- 一時間あたりの受付数を制限し、無制限な費用発生を防ぐ。
- 結果送信に失敗した場合、保存済み結果を再送でき、Jobを二重実行しない。

## リリース判定

### Telegram完全版（下書き・確認版）

次を全て自動テストと実機receiptで確認します。

1. サイトから1個、2個、3個の選択が引き継がれる。
2. 選択済み利用者の`/start`が再選択を要求せず総合司令室を復元する。
3. 10機能すべてで「この道具に頼む」から自然文を受付できる。
4. 総合司令室への自然文を、選択中の1〜3機能だけを使う司令Jobとして受付できる。
5. Job ID、状態、結果、Telegram message IDが保存される。
6. 結果から修正Jobを作成し、元Jobとの関係を保持できる。
7. 「今日やること」が同じJob正本を表示する。
8. 重複update、連打、別利用者、古いボタン、長すぎる入力、実行失敗、結果送信失敗を安全に処理する。
9. 外部へ何も送らず、成果物に「下書き／未実行」の境界が表示される。

### 外部自動実行版

各機能を外部自動実行対応と呼ぶには、その機能ごとに次が必要です。

- Kai所有providerへの接続確認
- 読み取りまたは実行adapter
- 実行前承認
- 冪等性キー
- provider readbackまたはreceipt ID
- 失敗時の再試行と停止条件
- 実データを使った成功・失敗のE2Eテスト

10機能のうち一つでも上記がない場合、サイトとBotはその機能を「自動実行済み」と表現しません。

## 現在の段階

2026-09-05に、10機能と総合司令室の自然文受付、最新選択の復元、同一Job正本の「今日やること」、結果からの修正・完了、原子的な重複・件数制限を実装しました。コードと自動テストだけでは本番稼働を証明しないため、Supabase migration、Railway Core、Mac側bridge、Telegram実送信のreceiptが揃うまでは「本番ready」と判定しません。外部providerを動かす版は、機能ごとのadapterと承認・readbackが揃ったものから別途実働化します。

# Rockstar_ibot 必需品配給設計 — 2026-08-28

## 1. 決定

Rockstar_ibot の対人支援は、受益者への現金給付ではなく、確認できた必需品または必要サービスを直接提供する方式へ移行する。

この方針で「配給」は、中央集権的な一律配布ではなく、個別の必要性を確認し、承認された品目を検証済み業者から調達して届ける **現物支援** を意味する。

## 2. 非交渉の境界

- 受益者へ現金、銀行振込、暗号資産、換金可能なギフトカード、無制限voucherを渡さない。
- 支援可否をモデルだけで自動決定しない。承認主体は権限を持つ人間または提携団体とする。
- 本人の希望と同意を確認し、その参照を必須にする。支援を受けるために不要な個人情報、思想、労働、宣伝を要求しない。
- モデルは不足項目の確認、重複検知、候補業者整理、進捗追跡を支援できるが、医療、住居その他の重大な適格性判断を単独で行わない。
- 調達費は受益者ではなく、検証済み業者または資格を持つサービス提供者へ直接支払う。
- 銀行振込基盤そのものは残す。承認済み業者への調達費、通常の事業支払い、顧客返金には利用できるが、支援受益者を振込先にする旧watcherは停止する。
- 生の住所、健康情報、本人確認資料は公開ledgerやGitへ保存しない。秘密vaultの参照だけを扱う。
- 「購入」「発送」「受領」はそれぞれ別の証跡で確認し、未確認を完了扱いしない。

## 3. 対象

初期カテゴリは次に限定する。

- 食料・飲料水
- 衛生用品・衣類
- 一時住居・寝具
- 電気・水道などの必須utility
- 資格を持つ医療・薬局・care providerへの直接手配
- 連絡手段に必要な通信機器または通信サービス
- 通院・避難・就労など目的が限定された交通
- 学習・就労・行政手続に必要な基本用品

法規制品、現金同等物、投機商品、嗜好品、転売目的の品目は対象外とする。

## 4. 状態遷移

1. `requested` — 本人または信頼できる紹介者が、仮名ID、本人同意参照、必要品を登録する。
2. `needs_evidence` — 不足する証拠または配送条件を確認する。
3. `review_ready` — 必要性、緊急度、重複、配送可能性の資料が揃う。
4. `approved_for_procurement` — 権限者が品目、数量、業者、上限を承認する。
5. `ordered` — 業者の注文番号と購入receiptを得る。
6. `dispatched` — 発送または予約receiptを得る。
7. `received` — 受領確認を得る。
8. `exception` — 欠品、不達、拒否、返金などを記録し、再判断へ戻す。

## 5. 資金経路

収益や寄付を使う場合も、資金はKai所有の調達treasuryに入り、承認済み注文の業者支払いだけに使用する。Stripe等の決済providerは受益者へのpayout railではなく、内部調達資金の受領・会計・業者支払いの証跡に限定する。

業者への支払い方法は、請求書、card、bank transfer等を許可する。銀行振込時は用途、承認参照、支払先確認参照、冪等keyを必須にし、調達planのvendor IDと確認済み振込先を一致させる。銀行口座詳細は実行境界だけで扱い、request ledgerや公開証跡へ保存しない。

## 6. 実装境界

- `skills/essentials-aid/` は現物支援requestの検証と調達planを担当する。
- `skills/ubi/` の人向け現金配布entrypointはlegacyとして停止する。
- `skills/ubi/gmo-furikomi.mjs` の基礎bank adapterは非支援受益者用途に残し、`skills/essentials-aid/lib/vendor-bank-payment.mjs`が承認済みvendor支払requestを作る。
- `skills/earn/run.sh` は利益wake後の自動UBI送金を呼ばない。
- live vendor、inventory、配送、医療providerは未接続であり、接続前に本人所有account、契約、法務、refund、在庫、配送receiptを検証する。

## 7. 完了条件

- 現金配布entrypointがfail closedで停止している。
- cash-like itemをrequest validatorが拒否する。
- 調達planは人間・提携団体の承認、必要性assessment参照、vendor verification参照を必須にする。
- 生の配送先をplanへ埋め込まず、private vault参照だけを保持する。
- 公開文書は「設計済み」と「live delivery」を区別する。

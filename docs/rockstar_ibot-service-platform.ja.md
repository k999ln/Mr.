# Rockstar_ibot

## 仕事を受け続けるAIから、仕事を商品にする基盤へ

Rockstar_ibotは、繰り返し発生するデジタル業務を、誰でも同じ条件で購入できる独立AIサービスへ変換するオープンソース基盤です。

従来の受託では、案件を探し、要望を読み解き、価格を交渉し、毎回異なる手順で成果物を作ります。Rockstar_ibotでは、その流れを逆転させます。先に提供範囲・入力・価格・納品物・品質基準を固定し、利用者は必要なサービスを選んで購入します。

```text
受託モデル
案件を探す → 個別交渉 → 毎回違う制作 → 手作業で確認 → 納品

Rockstar_ibot
サービスを選ぶ → 固定フォームへ入力 → 専用AIが制作 → 自動検査 → 証拠付き納品
```

Rockstar_ibotが目指すのは、何でも引き受けるAIではありません。範囲が明確で、結果を検査でき、何度でも同じ品質で提供できる小さなサービスを増やしていくことです。

## Service Cell

Rockstar_ibotでは、YouTube台本作成、SEO記事設計、LP制作などの各商品を「Service Cell」と呼びます。

Service Cellは、単なるプロンプトではありません。1つの商品として成立するために、次の契約をすべて持ちます。

| 契約 | 内容 |
|---|---|
| Intake Contract | 購入者が入力する情報、必須項目、ファイル形式 |
| Scope Contract | 対応すること、対応しないこと、修正可能範囲 |
| Production Contract | 制作手順、利用できる道具、データの出所 |
| Quality Contract | 合格条件、禁止事項、自動検査、再生成条件 |
| Delivery Contract | 納品物、形式、期限、証拠、再ダウンロード |
| Economy Contract | 価格、利用回数、返金条件、原価上限 |

各Cellの会話、ファイル、所有者プロフィール、利用可能な道具は分離されます。YouTube台本サービスがSEO顧客のデータを読んだり、別ユーザーの実績を自分の実績として回答したりすることは許可しません。

## 最初のサービス群

### YouTube Script Studio

テーマ、対象視聴者、動画の目的、希望時間、使用可能な事実を入力すると、収録可能な台本一式を納品します。

納品物：

- タイトル3案
- サムネイル文言
- 冒頭15秒のフック3案
- タイムコード付き台本
- B-rollと画面表示の指示
- CTAと次動画への接続
- 最初に検証するA/Bテスト案

再生数、登録者、収益は保証しません。購入者が提供していない統計、引用、実績、商品効果を創作しません。

### SEO Blueprint

キーワード、商品、対象読者、既存ページを入力すると、記事を書く前に必要な設計書を納品します。

納品物：

- 想定検索意図
- 読者が解決したい課題
- 見出し構成
- 各セクションの役割
- タイトルとメタ説明案
- 内部リンク候補
- 追加調査が必要な事実の一覧

検索順位を保証せず、確認できない検索量や競合数を事実として表示しません。

### Article Renewal

既存記事と変更目的を受け取り、内容を捨てずに読みやすさ、構造、情報不足を改善します。

納品物：

- 改稿済み本文
- 変更点一覧
- 削除・追加した理由
- 根拠が不足している箇所
- 公開前チェックリスト

### Landing Page Sprint

商品情報、ブランド素材、CTA、必要なフォームを入力すると、範囲を1ページに限定した公開可能なLPを制作します。

納品物：

- レスポンシブLP
- デスクトップ・モバイルプレビュー
- CTAとフォーム動作確認
- アクセシビリティと基本表示品質の検査結果
- ソース一式

大規模な業務システム、要件が確定していないアプリ、無制限の修正はこのCellに含めません。

### Customer Voice Digest

インタビュー、アンケート、サポート記録を、意思決定に使える顧客インサイトへ変換します。

納品物：

- 課題と要望の分類
- 発言根拠付きインサイト
- 頻度と重要度の整理
- 改善候補の優先順位
- 未確認事項

### Sales Reply Pack

問い合わせ内容と正式な商品条件を入力すると、相手の質問へ直接答える返信と見積り案を作成します。

納品物：

- 送信可能な返信文
- 質問への回答対応表
- 見積り条件
- 未確定事項
- 誤認や過剰約束の検査結果

## 1つの基盤、独立したサービス

Service Cellは互いに独立しますが、決済、注文、セキュリティをサービスごとに作り直しません。共有する部分は「Life Core」が担当します。

```text
                              ROCKSTAR_IBOT
                    Productized Service Platform
                                     │
                    ┌────────────────┴────────────────┐
                    │                                 │
                Life Core                       Service Cells
                    │                                 │
       ┌────────────┬────────────┬────────────┐       ┌────────────┬────────────┬────────────┐
       │            │            │       │            │            │
    identity      orders       billing  YouTube      SEO           LP
       │            │            │       Script      Blueprint     Sprint
       └────────────┬────────────┘       └────────────┬────────────┘
                    │                                 │
                 evidence ───────── quality gates ─ delivery
```

### Life Coreが共有するもの

- ユーザー認証とテナント境界
- 注文状態と重複実行防止
- 決済、返金、利用量
- 暗号化されたファイル保管
- 保存期限、削除、データ出力
- 実行履歴と証拠
- 通知と再納品
- 原価と処理時間の計測

### 各Service Cellだけが持つもの

- 商品固有の入力スキーマ
- 商品固有のAI指示
- 利用可能な道具とデータ
- 成果物テンプレート
- 品質テスト
- 対応範囲と拒否条件
- 価格と原価上限

## 注文から納品まで

1. 利用者がサービスを選び、価格と納品物を確認します。
2. 固定フォームへ必要情報を入力します。
3. Intake Contractが不足、危険な内容、範囲外の依頼を検出します。
4. 注文専用の隔離ワークスペースを作成します。
5. Service Cellが成果物を制作します。
6. 決定論的検査とAI品質審査を実行します。
7. 不合格なら納品せず、範囲内で修正または返金判定へ進みます。
8. 合格した成果物、検査結果、生成時点をまとめて納品します。
9. 実際の納品receiptが記録された時だけ注文を完了扱いにします。

モデルが「完成しました」と発言しただけでは完了になりません。ファイルの存在、形式、内容、検査結果、配送結果を確認します。

## 検証済みプロフィール

サービスが提供者の実績、SNS、職歴、能力を回答へ使う場合、その情報はリポジトリへ直接書きません。

所有者ごとの非公開プロフィールに保存し、次の条件を満たす事実だけをService Cellへ渡します。

- 現在のOSユーザーが所有する非公開ファイル
- 明示された利用目的
- 検証日時
- 必要に応じた有効期限
- 許可された公開URL
- 非公開の検証証拠

AIへ渡すのは公開可能な主張と検証時点だけです。証拠ファイル、顧客名、内部メモ、別サービスのプロフィールは渡しません。未設定、期限切れ、形式不正の場合は、事実を推測せず「利用可能な確認済み情報なし」として処理します。

## 収益モデル

初期はサービスごとの固定価格で販売します。利用者が何を受け取るか分からない状態で月額契約だけを先に売りません。

```text
単品購入
YouTube台本1本 / SEO設計1件 / LP1ページ

パック
YouTube台本4本 / SEO設計＋リライト / LP＋営業返信

継続プラン
毎月決まった本数・回数を利用
```

受託案件の売上から、利用者に見えない手数料を差し引く設計にはしません。Rockstar_ibotが直接提供するサービス、保存容量、利用回数、追加処理に対して明示的に課金します。

各サービスは次の数字を個別に計測します。

- 注文から納品までの時間
- 自動完了率
- 再生成率
- 返金率
- 人間による修正時間
- 1注文あたりのAI・保存・実行原価
- 品質検査の不合格理由
- 再購入率

人間が注文ごとに長時間介入しなければ成立しないCellは、サービスとして未完成です。個別対応で穴を埋めず、入力範囲を狭めるか、工程を改善します。

## ローカルとクラウド

Rockstar_ibotは、同じService Cellを2つの実行方法で提供します。

### ローカル / self-hosted

データを自分の端末に保持し、自分のモデルや認証情報でService Cellを動かします。

```bash
git clone https://github.com/Daisuke134/life-manager ~/rockstar_ibot
cd ~/rockstar_ibot
./scripts/local-up.sh
```

```bash
./scripts/local-up.sh status
./scripts/local-up.sh logs
./scripts/local-up.sh down
```

秘密情報はソースコードや注文データへ直接書かず、Keychainまたはtenant vaultの参照として解決します。

### クラウド

インストールせず、Webからサービスを購入・利用します。クラウド側でも注文ごとにテナントとService Cellを分離し、他の注文データをモデル文脈へ混ぜません。

ローカルとクラウドは別の商品ではありません。同じ入力契約、品質基準、成果物、証拠形式を使います。

## 現在の状態

Rockstar_ibotには、すでに次の再利用可能な構成要素があります。

- YouTube台本作成Cellの入力・制作・納品仕様
- 複数の文章・分析系サービスカタログ
- AI成果物の検査と納品確認
- 注文、返信、見積り、進捗を扱う実行部品
- ローカル実行スタック
- 証拠付き通知と台帳
- ユーザー別の検証済みプロフィール契約

一方、次の項目は全世界向けサービス基盤として未完成です。

- すべてのCellを購入できる統一ストア
- 完全なマルチテナント分離
- 統一決済と返金フロー
- 顧客データの保存期限、削除、エクスポート
- 署名済みリリースと段階配信
- 全テストが成功するリリースゲート

受託案件の自動探索、無許可のブラウザ送信、任意の仕事を引き受ける汎用エージェントは、公開サービスの中心に置きません。既存の制作・検査能力だけを、範囲の固定されたService Cellの内部で再利用します。

最初の3,000人へ提供する標準構成、個人別変更契約、容量仮定、段階配信、卒業条件は [`docs/rockstar_ibot-default-portfolio-3000.ja.md`](rockstar_ibot-default-portfolio-3000.ja.md) を正本とします。機械可読manifestは [`config/service-portfolios/default-3000.json`](../config/service-portfolios/default-3000.json) です。

## 原則

1. 1つのサービスは、1つの明確な結果だけを販売する。
2. 入力にない事実、実績、引用、数値を作らない。
3. 他ユーザー、他注文、他Service Cellのデータを混ぜない。
4. 品質を検査できない成果物は自動納品しない。
5. receiptのない処理を完了と報告しない。
6. 対応範囲を広げる前に、再現性と採算を証明する。
7. 人間の個別対応を、サービスの正常な工程として隠さない。
8. 利用者がデータ、価格、処理内容を理解し、削除できる状態を保つ。

## Mission

繰り返せる仕事を、交渉や属人的な運用に依存しない利用可能なサービスへ変える。

人が生活時間を削って同じ説明、同じ見積り、同じ制作工程を繰り返さなくても、必要な成果物へ正直かつ安全にアクセスできる状態を作ります。
